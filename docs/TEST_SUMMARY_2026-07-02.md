# PhotoLib 测试总结与 Bug 修复目标

> 测试日期：2026-07-02
> 测试基线：`854db20` + 当前工作区功能改动
> 测试方式：独立 MySQL 测试库、Local Object Storage、API 自动化、关键 UI 验证、导出文件检查、构建回归

## 1. 总体结论

PhotoLib 核心业务闭环已经跑通：

```text
空库初始化
  → 管理员首次改密
  → 创建部长与校区负责人
  → 创建并启动项目
  → 创建、发布、接受图片需求
  → 上传并处理图片
  → 填报、退回、修改、确认工时
  → 提交并完成需求
  → 采用图片
  → 导出工时 XLSX 与图片 ZIP
  → 站内通知已读
  → 完成并重新开放项目
```

系统的项目、需求、图片、工时、采用、导出和通知数据链路可运行，前后端构建回归通过。但当前版本不建议直接作为验收完成版发布，主要原因是权限异常响应和图片被引标记两个关键缺陷尚未修复。

## 2. 测试结果

| 结果 | 数量 | 占比 |
|---|---:|---:|
| 通过 | 69 | 65.1% |
| 失败 | 8 | 7.5% |
| 阻塞 | 4 | 3.8% |
| 未执行 | 25 | 23.6% |
| 合计 | 106 | 100% |

说明：

- 8 个失败用例集中对应 2 个主要产品缺陷。
- 4 个阻塞用例依赖专用阿里云 OSS、DirectMail 账号和可控故障环境。
- 25 个未执行项主要为大文件、批量/ZIP 边界、过期 URL、更多 UI 兼容性及低优先级异常路径。

## 3. 已验证能力

### 3.1 初始化与账户

- 空库正确执行 Flyway V1～V3，最终 schema 版本为 3。
- 仅创建一个初始化管理员，并强制首次修改密码。
- 管理员成功创建 `MINISTER` 和 `CAMPUS_MANAGER` 两种权限账号。
- 校区负责人必须关联启用校区。
- 密码重置后旧密码失效，并再次要求首次改密。
- 用户停用后无法登录，重新启用后可恢复登录。
- 刷新令牌轮换、退出登录及退出后的刷新失效符合预期。
- 版本冲突返回 409，未覆盖较新账户数据。

### 3.2 项目与需求

- 项目完成 DRAFT → ACTIVE → COMPLETED → 管理员重新开放 ACTIVE。
- 需求完成 DRAFT → PUBLISHED → ACCEPTED → SUBMITTED → COMPLETED。
- 不同校区负责人无法接受其他校区需求。
- 没有可用图片时不能提交需求。
- 项目完成后采用等写操作被正确锁定。

### 3.3 对象存储与图片

- 成功签发上传票据并通过 PUT 上传 JPG。
- 服务端校验并异步处理图片至 AVAILABLE。
- 原图下载 SHA-256 与上传文件一致。
- 非需求参与人无法关联需求上传。
- GIF 等不支持格式返回 415。
- 图片可归档、恢复；已采用图片不可删除。
- 本地对象存储完整验证了与 OSS 相同的应用层上传/下载契约。

### 3.4 工时与导出

- 工时完成 DRAFT → SUBMITTED → REJECTED → SUBMITTED → CONFIRMED。
- 退回原因正确保存并通知填报人。
- 确认后的统计为拍摄 75 分钟、修图 45 分钟、合计 120 分钟。
- 工时 XLSX 成功生成，包含“工时统计”和“被引图片”两个工作表。
- 被引图片统计为 1 张；公式错误扫描为 0。
- 图片 ZIP 成功生成并包含正确图片。

### 3.5 通知与审计

- 账号创建、需求发布、需求接受、需求提交、工时退回、工时确认均生成站内通知。
- 校区通知接收范围正确。
- 单条已读和全部已读正常，未读数最终归零。
- 部署级关闭邮件时站内通知不受影响。
- 管理员可读取审计记录。

### 3.6 回归

- `npm run build`：通过。
- 后端资源、编译和 Surefire 测试：8/8 通过。
- 常规 Maven 生命周期在 `npm ci` 阶段遇到运行中 Vite 占用 `esbuild.exe` 的 Windows 文件锁；绕过前端重复安装后，后端测试全部通过。该项为测试环境冲突，不计产品缺陷。

## 4. 缺陷汇总

| ID | 优先级 | 缺陷 | 影响 |
|---|---|---|---|
| BUG-001 | P0 | 方法级 `@PreAuthorize` 拒绝被全局异常处理器转换为 HTTP 500，而不是 403 | 越权请求被误报为服务端故障，接口契约错误并污染监控 |
| BUG-002 | P0 | 图片采用后，图片列表/详情 API 不返回 `adopted` 或 `adoptionCount`，UI 也无已采用标记 | 用户无法识别图片是否被引，直接缺失验收需求 |
| BUG-003 | P1 | `POST /projects` 创建响应中 `version=null` | 客户端若直接更新会传入空版本并触发 500 |
| BUG-004 | P1 | XLSX 未设置合理列宽，负责人、校区、表头和拍摄者内容被截断 | 下载文件数据正确但阅读体验不合格 |

## 5. 下一步 Bug 修改目标

### 目标一：统一权限拒绝响应

优先级：P0

修改目标：

- 捕获 Spring Security 方法级 `AuthorizationDeniedException`/`AccessDeniedException`。
- 统一返回 HTTP 403、错误码 `FORBIDDEN`。
- 不再通过通用异常处理器记录为“Unhandled request error”。
- Web 层和方法级权限拒绝使用一致的错误结构。

验收标准：

1. 部长创建用户返回 403。
2. 校区负责人访问审计日志返回 403。
3. 校区负责人采用图片返回 403。
4. 校区负责人创建统计导出返回 403。
5. 部长访问邮件设置返回 403。
6. 部长重新开放项目返回 403。
7. 上述请求均不产生服务端 ERROR 堆栈。

建议自动化：

- 增加权限矩阵集成测试，覆盖 ADMIN、MINISTER、CAMPUS_MANAGER 三个角色。
- 对所有 `@PreAuthorize` 控制器至少增加一个允许和一个拒绝用例。

### 目标二：实现图片被引/采用标记

优先级：P0

修改目标：

- 图片列表与详情响应新增 `adoptionCount`，并可派生 `adopted = adoptionCount > 0`。
- 图库卡片显示“已采用”标记及采用次数。
- 图片详情显示采用状态；必要时提供采用项目列表入口。
- 采用和取消采用后，列表、详情与项目汇总数据及时刷新。
- 图库支持按“已采用/未采用”筛选，或明确删除尚未实现的接口文档描述。

验收标准：

1. 未采用图片返回 `adoptionCount=0`，UI 不显示已采用。
2. 首次采用后返回 `adoptionCount=1`，列表和详情显示“已采用”。
3. 同一图片被不同项目采用时次数正确累加。
4. 取消采用后次数正确减少；归零时标记消失。
5. 已采用图片删除仍返回状态冲突，只允许归档。
6. 排行、项目汇总与图片标记计数一致。

建议自动化：

- 为采用、重复采用、取消采用、项目完成锁定增加集成测试。
- 增加 PhotoView 映射测试，防止采用字段遗漏。

### 目标三：保证创建响应版本完整

优先级：P1

修改目标：

- 所有带乐观锁的实体在创建响应中返回非空 `version=1`。
- 检查项目、需求、用户、校区、工时等 INSERT 后返回对象。
- 对请求体中的空版本或缺失版本返回 400，而不是 500。

验收标准：

1. 创建项目响应立即包含 `version=1`。
2. 客户端可直接使用创建响应版本执行下一次更新。
3. 缺失、为空、过期版本分别返回明确的 400/409。
4. 不再出现 Jackson 将 `null` 映射到基本类型 `int` 导致的 500。

建议自动化：

- 增加“创建后立即更新/状态流转”集成测试。
- 对所有版本请求 DTO 增加空值校验测试。

### 目标四：改善 XLSX 可读性

优先级：P1

修改目标：

- 为两个工作表设置合理列宽或在写入后自动适配。
- 表头加粗、冻结首行并启用筛选。
- 分钟列使用整数格式并右对齐。
- 长文本不应遮挡相邻单元格。

验收标准：

1. 负责人、校区、拍摄者学号/姓名和全部表头完整可见。
2. 工时数值仍为 75、45、120；被引张数仍为 1。
3. Excel/WPS 打开无修复提示。
4. 导出集成测试和视觉预览均通过。
